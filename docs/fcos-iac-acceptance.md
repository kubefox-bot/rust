# Приёмка переносимого FCOS IaC

Дата: 2026-10-18. Конфигурация: [iac/fcos](../iac/fcos/README.md).
Это проверка первоначального окружения ОС; приложение и почтовые данные
в этих испытаниях не запускались и не изменялись.

## PASS: подготовка

- Реальные официальные Butane `--strict` и Ignition validator приняли JSON.
  До появления исходника Butane завершился ожидаемой ошибкой отсутствия файла.
- В JSON проверены публичный ключ, UID/GID, home/group, append вместо замены
  subid-файлов, владельцы и mode каталогов, linger, декодированный Zincati TOML.
- Работает подготовка с явными путями из другого CWD и staging с пробелами.
- Ошибки отсутствующего, пустого и неверного SSH-ключа, испорченного YAML
  и неподдерживаемой schema version не заменяют последний проверенный JSON.
- Соседний sentinel-файл не попадает в JSON; в staging копируются два
  именованных входа. Тест использует собственный одноразовый публичный ключ.
- Выполнен реальный контейнерный Bash-блок из README на отдельной копии
  репозитория с пробелами в пути, из вложенного каталога. Контрольная сумма
  совпала; пустой/неверный ключ сохранили JSON и checksum предыдущего результата.
- Выполнен native-tools Bash-блок README в отдельном временном Git-каталоге
  Linux FCOS aarch64 гостя. Бинарники извлечены из тех же закреплённых официальных
  images, без установки RPM. Генерация из вложенного каталога и проверка
  SHA-256 прошли; версии Butane/validator совпали с контейнерной проверкой.
- Команда проверки subid-диапазонов возвращает ненулевой код при пересечении.
- Git исключает локальный публичный ключ и сгенерированные результаты.

## PASS: одноразовая локальная ВМ

- FCOS загрузилась; административный SSH-доступ работает с предоставленным
  одноразовым ключом. SSH слушал только loopback-порт машины проверки.
- `hmail-center` имеет UID/GID 2000, home `/var/home/hmail-center`, shell Bash.
- Home и три `.config` каталога принадлежат `hmail-center:hmail-center`, mode 700.
- `Linger=yes`; `user@2000.service` активен без SSH-входа служебного пользователя.
- Login-shell с явно заданными XDG runtime/bus variables подключился к manager:
  `systemctl --user is-system-running` → `running`.
- `podman info` → rootless `true`, cgroups `v2`; `podman unshare` создал
  реальные user namespaces и подтвердил UID/GID mappings.
- Стандартные записи `core` сохранились; проверены все диапазоны без пересечений.
- Zincati в журнале подтвердил `periodic`, 60 минут и 03:00 Sunday UTC.
- После завершения SSH-сеансов и перезагрузки изменился kernel boot ID,
  сохранились доступ по прежнему ключу, linger, manager, rootless/cgroup v2.
  Записи subid не продублировались при повторной загрузке.

## Решения при реализации

1. Проверки ограничены IaC, инструкцией и disposable VM: Rust/web исходники
   не менялись, поэтому их полный rebuild/retest в этой задаче не выполнялся.
   Стоимость: здесь не переаудируются посторонние ошибки runtime MVP.
2. FCOS useradd автоматически выделил служебному пользователю дополнительный
   диапазон `589824:65536` перед нашим append. Сохранены оба разрешённых
   непересекающихся диапазона; `core:524288:65536` тоже сохранён.
   Фактическое mapping: namespace UID/GID 0 → host 2000, 1…65536 → 200000…265535,
   65537…131072 → 589824…655359. Не заменяем файлы целиком ради одного диапазона.
   Стоимость: служебному пользователю дополнительно доступны 65536 subordinate
   IDs; при восстановлении нужно учитывать полные mapping-файлы машины.

## NOT RUN

- Ручная установка **с live ISO на выбранный оператором диск**, передача
  Ignition отдельным носителем/HTTPS, `--copy-network` с реальной сетью.
- Hyper-V и VMware, x86_64 guest, прошивки/сеть конкретной организации.
- SELinux bind-mount доступ на Linux-хосте подготовки: контейнерный workflow
  выполнялся через Colima; штатный SELinux гостя оставался включён.
- OCI-образ центра, интерактивный init, приложение через Quadlet после reboot,
  Windows-агенты, mTLS и операции очистки в этой FCOS-ВМ.
- Фактическое обновление ОС и перезагрузка по окну Zincati, согласование
  с активными заданиями; автоматический backup/updater и CI/CD не реализованы.

В production запускать только конфигурацию с вашим публичным ключом,
проверив фактические сеть, диск, UID/GID ranges и соответствующую поставку.
Операторская последовательность: [README FCOS](../iac/fcos/README.md).

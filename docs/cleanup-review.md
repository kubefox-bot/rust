# Проверка полной очистки и Windows-службы

Дата: 15 октября 2026. Ветка `update`. Код новой серии: `732ba41..999af5b`.
Предыдущая поставка проверялась отдельно; её EXE не является новой сборкой.

Независимый read-only review `732ba41..24b7376` нашёл три Important,
Critical не найдено. Все три исправлены одной серией RED→GREEN (`c41b128`):

1. CLI молча игнорировал параметры перед подкомандой. Теперь такая комбинация
   отклоняется; параметры прямого запуска указываются после `preview`/`clean`.
2. Full preview учитывал SQL-кандидатов как удалённые остатки. Добавлены
   `selected_orphan_metadata`/`selected_orphan_recipients`; `orphan_metadata` и
   `orphan_recipients` растут только после подтверждённого удаления/проверки.
   Отчёт выполнения содержит `mode`, включая NDJSON.
3. Ошибка cleanup-настроек обходила silent-журнал. Путь журнала разрешается
   до валидации остальных настроек; доступный журнал получает invalid-отчёт
   без консольного вывода. Ошибки самого источника/пути до доступного sink
   остаются стартовой диагностикой stderr с exit 2.

Повторный review не заказывался: исправления подтверждены регрессионными
тестами и общей проверкой. Отложенных Minor замечаний нет.

Кросс-сборка дополнительно обнаружила native-only ошибку Send/Sync у handle
службы. Исправлено в `999af5b`: адаптер хранит проверенное имя, а каждый
нативный handle создаёт и освобождает внутри синхронной операции. Handle не
переживает await, unsafe Send/Sync не добавлялись. Compiler RED→GREEN и
Windows-only type assertion подтверждают контракт; это не runtime-проверка SCM.

## Решения во время исполнения

Ниже полный перечень Ruling этой серии, в порядке принятия, с ценой ошибки:

1. Продолжить в выделенном checkout `update`: сохранить ветку и пути поставки.
   Цена: появившиеся параллельные пользовательские изменения нужно сохранять.
2. Поместить Summary ошибки в Box после роста Err до 136 байт: убрать
   result_large_err без подавления lint. Цена: выделение памяти только при ошибке.
3. После успешного unlink повторять только проверку отсутствия. Цена: при
   постоянной ошибке проверки запись БД сохранится, даже если файл уже удалён.
4. Windows lock fixture использует handle без FILE_SHARE_DELETE вместо readonly.
   Цена: отдельная проверка настоящего ACL denial остаётся на Windows.
5. Windows-specific tests здесь только готовятся/собираются. Цена: реальный
   Server 2016, блокировки, ACL и SCM ещё нужно проверить на Windows.
6. Общие commit/rollback и SQL ID bindings вынесены у MySQL-владельца для двух
   одинаковых потребителей. Цена: два модуля и небольшой refactor обычного delete.
7. Проверку orphan CommitUncertain-счётчиков перенести из Task 2 в Task 4,
   где появился use case. Цена: доказательство orchestration появилось позднее;
   к завершению оно выполнено.
8. test:db включает ignored library EXPLAIN наряду с mysql integration.
   Цена: дополнительный тестовый экземпляр БД и test-only alias, без public hook.
9. ScanBatch отдельно хранит visited_entries: ограничить порции и через пустые
   каталоги. Цена: поле DTO и согласованная проверка прогресса в core.
10. Общий worker scheduler принимает типизированные targets/outcomes двух режимов,
    без выдуманных SQL IDs. Цена: generic внутренняя сигнатура.
11. Существующий component validator доступен account layout. Цена: один public
    helper core вместо второго набора правил Windows paths.
12. Общие retention parsers перенесены в config для CLI/env/menu. Цена: внутреннее
    перемещение файла, прежний синтаксис сохранён.
13. Общие поля Settings появились до потребителей Tasks 6/7. Цена: временные
    dead-code warnings; в финальной переносимой проверке они устранены.
14. Tokio time/sync включены в Task 7, поскольку native wait уже требует таймер.
    Цена: изменение manifest на одну задачу раньше.
15. Подготовительные Report-ошибки в Box после роста до 144 байт. Цена: одно
    выделение памяти на ошибку, без подавления Clippy.
16. Журнал проверяется до SCM, затем callback открывает собственный handle
    с SCM cancellation token. Цена: второй open может дать ошибку запуска SCM;
    до него нет почтовых/SQL side effects.
17. Если ожидание перескочило локальную дату слота, пропустить его. Цена:
    пропущенная очистка ждёт следующего будущего слота.
18. SCM fixtures создают только уникальные hMailCleanerFixture_* службы,
    с явным scm_fixture.exe, без почты/БД. Цена: тестовый EXE и admin Windows CI;
    здесь runtime не исполнен.
19. Ошибка источника/пути до доступного журнала остаётся в stderr, как допускает
    Task 6. Цена: невалидный/недоступный sink не может записать собственную ошибку.
20. Handle windows-service 0.8.1 нельзя переносить между потоками. Хранить имя
    и открывать/закрывать handle внутри синхронной операции, без unsafe casts
    и отдельного постоянного worker. Цена: polling повторно открывает handle;
    конкурентная внешняя замена самой службы во время очистки не поддерживается.

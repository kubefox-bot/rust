# Криптографический формат v1

Формат хранит шифрованные технические записи в обычной SQLite.
История, идентификаторы и названия серверов остаются обычными данными.
SQLCipher для этого формата не нужен.

## Ключи и вычисления

- DEK: 32 случайных байта, отдельный стабильный UUID ключа.
- Argon2id v1.3: m=32768 KiB, t=3, p=1, соль 16 байт, результат 32 байта.
- Проверочный PHC и парольная обёртка используют разные соли и два
  последовательных вычисления. Сохранённый PHC не используется как ключ.
- Одна принадлежащая операции арена из 32768 блоков по 1024 байта
  используется повторно. Zeroizing очищает её на успешном и ошибочном выходе.
- Recovery key: независимые 32 случайных байта; строка
  `hmc-recovery-v1:` + 43 Base64URL символа без padding.
  Для этого случайного ключа используется HKDF, без Argon2.
- XChaCha20-Poly1305: ключ 32 байта, новый случайный nonce 24 байта
  для каждого seal, tag 16 байт в конце ciphertext.

KdfGate допускает одно вычисление через try acquire. Permit принадлежит
blocking closure, поэтому отмена ожидающего HTTP task не допускает второй
KDF поверх ещё работающего первого. Пароли ограничены 12..1024 Unicode
scalar values и 4096 UTF-8 байт; нормализация и trim не выполняются.

Поддерживаются только заданные Argon2id алгоритм/версия/параметры,
16-байтная соль и 32-байтный PHC output. Проверка выполняется до создания
арены; произвольные параметры из БД не передаются вычислителю.
Feature parallel у argon2 и автоматический выбор других криптопровайдеров
не включаются.

## AAD

AAD кодируется бинарно; порядок ключей JSON на него не влияет.
Все UUID — 16 сетевых байтов `Uuid::as_bytes()`. Целые — unsigned big-endian.

| Поле | Длина |
| --- | --- |
| ASCII `hmail-cleaner/aad/1` | 19 байт |
| format_version = 1 | u16 |
| record kind | u8 |
| cipher = 1, XChaCha20-Poly1305 | u8 |
| vault_id | 16 байт |
| record_id | 16 байт |
| record_version | u64 |
| key_id, UUID DEK | 16 байт |
| key_generation | u64 |
| derivation | По таблице ниже |

| Kind | Код |
| --- | --- |
| profile | 1 |
| ca_key | 2 |
| center_client_key | 3 |
| password_wrap | 4 |
| recovery_wrap | 5 |

Derivation record: один байт 0, без дополнительных полей.

Derivation password: байт 1, account_id (16), Argon2id code 1 (u8),
version 19 (u32), memory_kib 32768 (u32), passes 3 (u32), lanes 1 (u32),
output_bytes 32 (u16), salt_length 16 (u16), salt (16).
Account_id совпадает с record_id обёртки.

Derivation recovery: байт 2, account_id (16), HKDF-SHA256 code 1 (u8),
salt_length 32 (u16), salt (32).

У обычной записи derivation обязан быть record. У обёрток допустима только
соответствующая им derivation. Нулевые UUID, версии и поколения запрещены.
У каждой обёртки своё поколение. Версия учётной записи для CAS не входит
в AAD профиля; смена пароля не требует перешифрования профилей.
Полная ротация DEK в MVP не реализуется.

Владелец записи строит ожидаемый EnvelopeHeader по запрошенному ID, версии,
виду записи и identity хранилища, затем передаёт его в open_record.
Проверяется совпадение ожидаемого контекста с envelope и AEAD tag;
перестановка целого envelope между профилями отклоняется.

## HKDF

HKDF-SHA256 выдаёт 32 байта. Для record и password-wrap salt равен
16 байтам vault UUID; для recovery-wrap используется отдельная случайная
32-байтная соль из derivation.

Info начинается с ASCII `hmail-cleaner/v1/`. Для записей далее идут
`record/`, один из `profile`, `ca-key`, `center-client-key`, `/`.
Для обёрток далее идут `password-wrap/` или `recovery-wrap/`.
После текстовой части во всех случаях следуют record_id (16), vault_id (16),
key_id (16), key_generation (u64 BE).

IKM record — DEK; IKM password-wrap — результат Argon2id с отдельной солью;
IKM recovery-wrap — случайный recovery key. Ключи назначения не хранятся.

## Хранение и границы

JSON — контейнер заголовка, nonce и ciphertext. Ciphertext кодируется
каноническим Base64URL без padding, nonce — массив ровно из 24 байтов.
Plaintext ограничен 64 KiB; ciphertext содержит от 16 до 65552 байт.
Обе обёртки содержат ровно 32 байта DEK и 16 байт tag.

Для ввода с диска используются AccountMaterial::decode (до 8192 байт)
и EncryptedRecord::decode (до 128 KiB). Предел проверяется до JSON parsing,
включая возможные escaped strings. Storage owner ограничивает размер
SQL blob до загрузки и затем вызывает эти методы. Неподдерживаемая версия,
нарушение размера, неверный tag или повреждение БД возвращают ошибку;
пустой профиль вместо ошибки не создаётся.

Zeroizing очищает принадлежащие приложению пароли, ключи, открытый payload
и арену. Это не обещание удаления всех копий из регистров, сторонних
библиотек, swap, дампов или старых резервных копий. Размер арены 32 MiB
не является оценкой полного RSS процесса; ресурсы измеряются отдельно.

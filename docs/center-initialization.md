# Локальное создание центра

Сборка отдельного компонента: `mise run build:center`.

Перед первым запуском выполните:

```sh
hmail-cleaner center init --data-dir /absolute/path/to/center-data
```

Команда спрашивает логин, скрыто вводимый пароль и его повторение. Затем
показывает новый recovery key: сохраните его отдельно от каталога центра
и подтвердите сохранение повторным вводом. До подтверждения учётная запись
не записывается. Ошибка фиксации означает, что выданный кандидат не стал
действующим ключом. Повторный init не заменяет существующую учётную запись.
Секреты через аргументы командной строки не передаются.

Все команды одного каталога используют исключительную блокировку файла.
Повреждённая база и неизвестная версия схемы блокируют открытие: init
не переименовывает и не перезаписывает их. Не удаляйте SQLite/WAL, пытаясь
повторить настройку.

Внутренний `CenterStore::backup` создаёт новую папку, согласованный snapshot
через SQLite VACUUM INTO, manifest с версией схемы и vault identity,
а также существующую пару HTTPS bootstrap-файлов. Не копируйте работающий
`center.sqlite` отдельно от WAL. Копия сохраняет прежние пароль/recovery;
дальнейшая смена реквизитов не отзывает уже созданную копию.

На этапе B2 `center run --data-dir …` является временным каркасом:
доступен только loopback `/healthz`, браузерные API отсутствуют.
HTTPS и сессии добавляются этапом B3; этот каркас не является готовой
поставкой для сети.

# Ручные задания центра

Перед сетевой отправкой центр сохраняет публичное намерение и занимает один
общий слот в SQLite. Повтор HTTP-запроса с тем же `job_id` и теми же параметрами
возвращает существующий запуск; изменение параметров этого ID — конфликт.
Потеря ответа, недоступность агента и GET 404 сохраняют слот. Перезапуск центра
и новый вход выполняют только lookup; повторный PUT очистки не используется.

Очистка требует успешного завершённого preview, той же версии профиля,
cutoff, fast/full, лимитов и подтверждённой политики службы. В намерении preview
сохраняется будущая политика очистки; сам preview всегда отправляется с
RequireStopped и не останавливает почту. Оценка preview не фиксирует состав
почтового дерева: новые письма и изменения между запусками возможны.

Агент сохраняет первое известное состояние почтовой службы в квитанции.
Для Clean/Manage центр освобождает слот после terminal receipt, исправного
агента той же эпохи и свежего наблюдения исходного состояния службы.
При Interrupted требуется отдельное наблюдение: отчёт сам не подтверждает
восстановление. Неизвестное исходное состояние удерживает слот для разбора.
Отмена неизвестного запуска использует долговечную tombstone агента, чтобы
задержанная первоначальная команда уже не могла начать очистку.

После входа один наблюдатель центра согласует занятый слот и читает SSE агента.
Сетевой сбой или resync ведёт к lookup с интервалом повторения 5 секунд;
он никогда не отправляет команду заново. До входа наблюдателя нет. Выход
закрывает транспорт и очищает ключи сессии; принятая работа остаётся у агента.
Пароль MySQL не хранится в намерении, квитанции или истории центра.

Агент хранит подробные списки файлов трёх последних завершённых preview,
включая отменённые, ошибочные и прерванные, плюс список активного preview.
Старые списки удаляются при завершении/отмене задания и восстановлении после
перезапуска; квитанции и итоговые счётчики остаются. Для удалённого списка API
возвращает 410 Gone. Освободившиеся страницы SQLite повторно используются;
сам файл БД автоматически не сжимается.

Отмена проверяется между пачками загрузки MySQL и предварительного полного
обхода, а также между основными пачками очистки. Текущий SQL-запрос или файловая
пачка завершается перед выходом. Прерванная подготовка получает статус
«Отменено»; восстановление исходного состояния службы завершается до terminal
receipt.

Браузер получает SSE с server/job ID, эпохой и ревизией. На подключение,
перезапуск и отставание он перечитывает снимок. Шина ограничена 256 событиями,
кадр — 4096 байтами, число SSE-подключений — 16. Большой кадр заменяется resync.
Terminal receipt сохраняется до публикации. История читается курсором по
монотонному sequence: по умолчанию 50, максимум 100 записей. Неизвестное
количество оставшихся файлов остаётся null, объём выбранного и удалённого
показывается раздельно и не объявляется измерением свободного места диска.

## Веб-панель

Откройте центр по настроенному HTTPS origin и войдите суперадмином. Выбор сервера
хранится в URL вкладки (`?server=<UUID>`), поэтому другая вкладка не меняет цель
подтверждения. Экран получает текущую версию профиля, последнее задание и общую
занятость через `/api/v1/servers/{id}/cleanup-context`, без чтения технического
профиля или списка истории.

Предпросмотр проверяет профиль и вычисляет границу на агенте. Полный предпросмотр
при работающей почтовой службе отказывает без её остановки. Для очистки нужен
успешный предпросмотр и отдельное подтверждение; разрешение остановить службу
также явно показывается в подтверждении. Изменение параметров отменяет прежний
предпросмотр. Параметры подтверждённой команды не пересчитываются в браузере.

Один SSE на вкладку передаёт изменения выбранного сервера. Изменение размера
журнала не создаёт новое соединение. «Развернуть журнал» сохраняет сервер,
прогресс и футер; Escape возвращает обычный вид и фокус. В окне остаются последние
1000 событий. Неизвестные итоги сверки показываются как «Не проверено»;
выбранные и удалённые байты разделены, свободное место диска не вычисляется из них.

При неизвестной доставке доступны проверка исходного ID и отмена; автоматической
повторной очистки нет. Выход, смена страницы и выбор другого сервера не отменяют
принятое агентом задание. После нового входа центр сверяет прежнее задание с
агентом. Пока восстановление службы не подтверждено, тяжёлая операция остаётся
занятой. Pagehide скрывает данные и закрывает SSE, pageshow проверяет сессию до
повторного открытия данных; фоновые события не продлевают таймаут бездействия.

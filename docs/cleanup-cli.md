# hMail Cleaner: инструкция

## Запуск и файл настроек

Запустите `hmail-cleaner.exe` без аргументов — откроется русское меню.
Скопируйте `cleaner.env.example` в `cleaner.env` рядом с EXE и заполните настройки.
Текущая папка CMD/PowerShell не влияет на поиск автоматического файла.

```cmd
hmail-cleaner preview
hmail-cleaner clean --manage-service
hmail-cleaner clean --scan full --before "2024-09-15T23:00:00" --manage-service
hmail-cleaner preview --env-file "C:\private\cleaner.env" --plain
```

Аргументы задаются после подкоманды. Приоритет значений: аргументы → окружение
Windows → выбранный env-файл → defaults. Явный `--env-file` полностью заменяет
автоматический файл. Не читается произвольный `.env` из текущего каталога.
Пути Windows с обратными слэшами заключайте в одинарные кавычки, как в примере.
Отсутствующий автоматический файл допускается; найденный повреждённый файл
и недоступный явно указанный файл приводят к ошибке. Изменения через меню
действуют только в текущем процессе, env-файл не переписывается.

Обязательные настройки: `DATABASE_URL`, `HMAIL_DATA_DIR`, `HMAIL_INI`, а также
`HMAIL_OLDER_THAN` или `HMAIL_BEFORE`. Пример находится в
[cleaner.env.example](../cleaner.env.example). Права SQL: SELECT на `hm_messages`,
`hm_accounts`, `hm_imapfolders`, `hm_message_metadata`, `hm_messagerecipients`;
DELETE на `hm_messages`, `hm_message_metadata`, `hm_messagerecipients`.
Поддерживаются проверенная схема hMailServer и таблицы InnoDB.

`DATABASE_URL` имеет форму `mysql://user:password@127.0.0.1/database`.
Специальные символы пароля кодируются как часть URI. URI и пароль не выводятся
в штатные сообщения. Храните файл настроек с доступом только для нужной учётной
записи сервера. Локальные старые `.env` сохраняются, но не загружаются автоматически.

## Даты и режимы

- `--older-than 30d`, `1mo`, `2y`: дни, календарные месяцы или годы.
- `--before "2024-09-15T23:00:00"`: точная граница местного времени сервера.
- Дата без времени означает полночь. Сравнение строгое: `CreationTime < cutoff`.
- При отсутствии файла возраст записи определяется `messagecreatetime`.
- На одном уровне конфигурации нельзя задавать и период, и точную дату.
  Аргумент CLI заменяет границу из окружения/env. При периоде дата пересчитывается
  перед каждым запуском; для воспроизводимого сравнения задавайте `--before`.
- Неоднозначное/несуществующее время при переходе часов отклоняется.
  Дата создания файла после копирования может отличаться от даты письма.

**Оба режима** обходят заданный корень и все вложенные каталоги, включая корневые
файлы очереди, `#Public` и нестандартную вложенность. Обрабатываются обычные `.eml`
без учёта регистра расширения; файлы других расширений сохраняются. Symlink и
junction пропускаются; сам корень и его разрешённые родители проверяются.

- `fast`: один потоковый обход, удаление старых файлов и связанных записей,
  обработка старых записей уже отсутствующих файлов. Предварительного подсчёта
  всего дерева нет; общий объём сканирования неизвестен.
- `full`: дополнительно проверяет дерево перед очисткой, очищает исторические
  metadata/recipients без родительского письма и после очистки повторно сверяет
  количество оставшихся старых файлов. Оставшиеся старые файлы дают ненулевой
  код результата; подробные ошибки обработки сохраняются в отчёте/журнале.

Это изменение относительно прежних версий: fast тоже обходит диск, а корень
Data больше не исключается. Карта БД загружается порциями по первичному ключу,
хранит не более 1 000 000 строк и не содержит тел писем. Неоднозначные ссылки
на один путь сохраняются с ошибкой. Неоднозначный/некорректный путь БД блокирует
начало файловой очистки. Два одинаковых GUID в разных ящиках сопоставляются по
полным путям; одного совпадения GUID недостаточно для удаления записи.

Путь Data должен совпадать с `[Directories] DataFolder` указанного INI.
Быстрый предпросмотр допускает работающий hMailServer; при изменении хранилища
его результат ориентировочный. Полный предпросмотр требует остановки службы.
Для clean можно заранее
остановить службу или передать `--manage-service`: программа восстановит
исходное состояние после обработки, в том числе при ошибке или отмене.
Другие экземпляры очистителя блокируются SQL-lock; блокировка удерживается
до окончания восстановления службы и закрытия соединения.

## Порядок очистки и ошибки

1. Проверить настройки, схему, SQL-права и состояние почтовой службы.
2. Загрузить карту путей БД с учётом доставленных писем и очереди.
3. Обходить дерево пакетами; отбирать `.eml` по дате создания.
4. Повторно сверить CreationTime, LastWriteTime и размер, удалить файл,
   подтвердить отсутствие. Временные ошибки повторяются ограниченное число раз.
5. Транзакционно удалить metadata, recipients и сообщение; проверить отсутствие
   строк. Изменившаяся запись БД блокирует транзакцию.
6. Удалять полностью просмотренные пустые каталоги снизу вверх, включая те,
   которые были пустыми до запуска. Корень Data сохраняется.
7. Для full выполнить дополнительные проверки, затем восстановить службу.

Ошибка удаления файла сохраняет связанные строки БД. Если файл удалён, но SQL
завершился ошибкой, повторный запуск обработает отсутствие файла по дате БД.
Если дата БД свежая, такая отсутствующая запись сохраняется: прежний CreationTime
уже недоступен, а постоянный журнал удалений программа не ведёт.
Потеря подтверждения COMMIT завершает запуск с ошибкой; повторите его для сверки.
Ctrl+C завершает начатый пакет и освобождает ресурсы. Внешние программы не должны
изменять хранилище во время очистки. Предпросмотр ничего не удаляет и не является
сохранённым планом последующего clean.

## Экран, журнал и автоматизация

В интерактивной консоли сверху показаны последние пять действий, посередине —
текущая операция и счётчики, снизу — время, скорость, анимация и прогресс-бар.
Анимация обновляется независимо от работы диска/БД; время последнего изменения
счётчиков помогает отличить активный интерфейс от реального продвижения очистки.
Процент относится только к этапу с известным количеством работы. Нет фиктивного
общего процента. В preview объём помечается как потенциальный.

Меню, текстовый вывод и файловый журнал — на русском. Журнал UTF-8 создаётся
только по `--log-file` или `HMAIL_LOG_FILE` с абсолютным путём. Сохраняется ротация:
10 МиБ, три архива. После запуска из меню итог остаётся до Enter. Прямые CLI-команды
и служба не ожидают нажатия клавиш.

`--plain` отключает полноэкранную панель. Перенаправление вывода автоматически
выбирает обычный текст. `--json` выводит NDJSON с прежними машинными ключами и
числами в исходных единицах. Дополнительные поля: `selected_files`, `selected_bytes`,
`total_scan_files`, `verified_files`, `remaining_old_files`. Последнее поле равно
`null`, пока заключительная сверка не завершена, в том числе в fast и preview;
нулевое значение означает именно завершённую сверку без остатков.
Объём — сумма размеров файлов, а не прямое измерение свободного места диска.
Текстовый журнал остаётся русским
независимо от JSON stdout. `--silence` отключает вывод и вопросы, требует журнал
и несовместим с меню/JSON. Неинтерактивный запуск без команды завершается
с подсказкой, не ожидая ввода.

На время полноэкранного запуска Windows QuickEdit выключается локально для
этого процесса, затем режим консоли восстанавливается. Ctrl+C сохраняется.
Если панель недоступна, программа переходит к обычному выводу. В старом CMD
при ручном выделении/остановке вывода можно нажать Esc и проверить QuickEdit.
Гипотеза о причине прежних остановок требует проверки на реальном сервере.

## Прежняя служба с расписанием

Очистка по расписанию удалена. Команда `service run` завершается с кодом 2
до чтения конфигурации и не выполняет очистку. `HMAIL_RUN_AT` больше не читается.
Для ручного запуска используйте `preview` или `clean`; агент центра получает
явные команды по сети и не запускает очистку самостоятельно после старта.

При переходе со старой версии сначала остановите службу `hMailCleaner` через
SCM. Замена EXE на диске не завершает уже работающий старый планировщик.
Удаление прежней службы и установка агента выполняются отдельным явным шагом.

## Разработка и сборка

Rust закреплён в `mise.toml`. Node.js, Yarn, Tauri и WebView2 не используются.

```sh
mise run check
mise run test:db
mise run build:exe
```

На Windows нужны MSVC Build Tools и Windows SDK. На macOS нужен работающий Docker:
используется `messense/cargo-xwin:0.23.1`, Rust 1.99.1 и target
`x86_64-pc-windows-msvc` со статическим CRT. Исходники передаются через Docker cp;
env-файлы не копируются. SDK/toolchain/artifacts кэшируются в Docker volume
`hmail-cleaner-build-cache`. Можно выбрать контекст через
`HMAIL_BUILD_DOCKER_CONTEXT`; сначала используется текущее подключение Docker, затем доступный работающий
контекст проекта `colima-hmail-cleanup`. Задача не запускает и не останавливает
Docker/Colima сама.
Первый запуск может долго загружать Rust и Windows SDK. SDK устанавливается
согласно механизму лицензирования cargo-xwin.

Команда публикует `hmail-cleaner.exe` и `hmail-cleaner.exe.sha256` в корень проекта
только после успешной компиляции и вычисления checksum. Предыдущий EXE сохраняется
при ошибке компиляции. При ошибке замены выполняется восстановление из временной
резервной копии. Артефакты исключены из Git. `--version` показывает версию,
ревизию исходников и время сборки.

Для интеграций используется отдельный MySQL 5.7.21 на loopback:13306 через
`mise run test:db`, не рабочая БД. После тестов: `mise run db:down`.
Существующие `build` и `build:windows` сохраняют сборку в target.

Целевая среда — Windows Server 2016/1607. Cross-build и тесты на macOS
подтверждают компиляцию и переносимую логику; они не заменяют запуск CMD,
PowerShell, службы и QuickEdit непосредственно на Server 2016.
